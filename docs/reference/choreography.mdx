```ts
import { choice, component, isEquals, peek, pick, sequence, simplify, walk } from "auth-dance";
```

See [The choreography](/docs/concepts/choreography) for the ideas behind these functions.

## Types

```ts
type AuthDanceChoreography = AuthDanceChoreographyComponent | AuthDanceChoreographyChoice | AuthDanceChoreographySequence;

interface AuthDanceChoreographyComponent {
	kind: "component";
	component: string;
}

interface AuthDanceChoreographySequence {
	kind: "sequence";
	components: AuthDanceChoreography[];
}

interface AuthDanceChoreographyChoice {
	kind: "choice";
	components: AuthDanceChoreography[];
}
```

Each type also exists as a valibot schema of the same name, to parse a choreography at runtime.

## component

```ts
function component(name: string): AuthDanceChoreographyComponent;
```

Wraps a component name in a component node. The state machine raises `UnknownComponentError` for a name that `components` does not declare.

## sequence

```ts
function sequence(...components: Array<AuthDanceChoreography | string>): AuthDanceChoreographySequence;
```

Builds an ordered run. The owner performs every child, from the first to the last. A plain string is sugar for `component(name)`.

```ts
sequence("email", "password");
```

## choice

```ts
function choice(...components: Array<AuthDanceChoreography | string>): AuthDanceChoreographyChoice;
```

Builds a fork. The owner performs exactly one branch. A plain string is sugar for `component(name)`.

```ts
choice("password", "passkey");
```

## pick

```ts
function pick(count: number, ...components: Array<AuthDanceChoreography | string>): AuthDanceChoreographyChoice;
```

Builds a choice of every ordered permutation of `count` components, one sequence per permutation. Order matters, so a pair gives one branch per order. A `count` above the number of components gives a choice with no branch.

```ts
pick(2, "totp", "sms", "backup-code"); // any 2 of 3, in any order
```

## isEquals

```ts
function isEquals(a: AuthDanceChoreography | null, b: AuthDanceChoreography | null): boolean;
```

Compares two nodes by structure. Two `null` values are equal, and a `null` never equals a node. The comparison respects order, so `choice(a, b)` and `choice(b, a)` are two different policies.

## simplify

```ts
function simplify(choreography: AuthDanceChoreography): AuthDanceChoreography;
```

Rewrites a tree into a smaller tree with the same policy. It lifts a child of the same kind into its parent, drops an equal duplicate child, and replaces a node of one child with that child.

```ts
simplify(sequence(sequence("a", "b"), choice("c"))); // sequence("a", "b", "c")
```

## walk

```ts
function walk(choreography: AuthDanceChoreography): Generator<{
	component: AuthDanceChoreographyComponent | null;
	path: AuthDanceChoreographyComponent[];
}>;
```

Walks every path through the tree. Each yield holds one step and the ordered steps before it. A step appears one time per path that leads to it. An entry with a `component` of `null` ends a complete path, and its `path` is that complete path.

```ts
for (const { component, path } of walk(choice(sequence("email", "password"), "passkey"))) {
	if (component === null) console.log(path.map((step) => step.component));
}
// ["email", "password"]
// ["passkey"]
```

## peek

```ts
function peek(
	choreography: AuthDanceChoreography,
	path?: string[],
): AuthDanceChoreographyComponent | AuthDanceChoreographyChoice<AuthDanceChoreographyComponent> | null;
```

Reports what the dance asks for after `path`, the names of the steps already done. An empty path asks for the first step. It returns the next step, a choice of the alternatives, or `null` when `path` completes the dance. It throws `ComponentNotInChoreographyError` when no step sits at `path` and no complete path matches it.

```ts
peek(sequence("email", "password"), ["email"]); // component("password")
peek(choice(sequence("email", "password"), "passkey")); // choice(component("email"), component("passkey"))
peek(sequence("email", "password"), ["email", "password"]); // null
```
