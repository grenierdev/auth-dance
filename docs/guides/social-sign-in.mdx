`auth-dance/components/oauth2/*` holds one component per provider: `apple`, `facebook`, `github`, `gitlab`, `google`, `microsoft` and `x`. Each one is an identification that proves control: the exchange of a code that only the provider issues shows that the owner controls the account. So a provider account can be a complete path on its own.

## 1. Register an app at the provider

Register an OAuth app at the provider, and give the page of your client that the provider sends the owner back to as its redirect URI. For GitHub, register an OAuth app or a GitHub App and give its callback URL. Each provider page of the [components reference](/docs/reference/social-providers) says what to register.

## 2. Add the component

```ts
import { choice, sequence } from "auth-dance";
import { GitHubAuthDanceComponent } from "auth-dance/components/oauth2/github";

const auth = createAuthDance({
	api: {
		choreography: choice(sequence("email", "password"), "github"),
		components: {
			email: new EmailAuthDanceComponent({ channel: "email", challenge: "otp" }),
			otp: new OtpAuthDanceComponent({ channel: "email" }),
			password: new PasswordAuthDanceComponent(process.env.PASSWORD_PEPPER!),
			github: new GitHubAuthDanceComponent({
				clientId: process.env.GITHUB_CLIENT_ID!,
				clientSecret: process.env.GITHUB_CLIENT_SECRET!,
				redirectUrl: "https://app.example.com/callback",
			}),
		},
		// …
	},
});
```

The client secret stays on the server. The record on the identity holds the name of the step and the id of the account at the provider, and nothing more.

## 3. Send the owner to the provider

The component is headless. The client moves the owner between your page and the provider. The prompt has the type `oauth2`, and `options.authorizationUrl` is the whole authorization URL.

The client keeps the dance in `sessionStorage` before it leaves the page:

```ts
import { AuthDanceClient, webStorageStore, type AuthDanceClientChoreographySnapshot } from "auth-dance/client";

const client = new AuthDanceClient({ baseUrl: "https://auth.example.com" });
const store = webStorageStore<AuthDanceClientChoreographySnapshot>("auth-dance.dance", sessionStorage);

const dance = await client.signIn({ store });
await dance.choose("github");
location.assign(dance.current!.options!.authorizationUrl as string);
```

## 4. Come back from the provider

The provider sends the owner back to `redirectUrl` with `code` and `state` in the query. On that page, resume the dance and submit the query under the name of the step:

```ts
const resumed = await client.resume(store);
await resumed!.submitPrompt(Object.fromEntries(new URLSearchParams(location.search)), { name: "github" });
```

The component checks `state`, exchanges `code` at the token endpoint of the provider, and finds the identity that holds the account. The sign-in then ends with tokens.

## The same prompt in every flow

The prompt is the same in every flow. A sign-in and the first step of a recovery look up the identity that holds the account. A sign-up, an `enroll("github")`, a `rotate("github")` and the reset of a recovery link the account. An account that already belongs to another identity raises `IdentificationTakenError`.

A second call to `getPrompt` replaces the authorization in progress, so only the last authorization URL the client read answers. A redirect that gives back the correct `state` removes it, so one authorization answers one time. An authorization lasts `ttl` seconds, 300 by default, or until the state of the dance expires.

## OpenID Connect providers

`apple`, `gitlab`, `google` and `microsoft` extend `OidcAuthDanceComponent` from `auth-dance/components/oidc`. They read the endpoints from the discovery document of the issuer, send a `nonce`, and read `sub` from the ID token. For any other OpenID Connect provider, use `OidcAuthDanceComponent` directly:

```ts
import { OidcAuthDanceComponent } from "auth-dance/components/oidc";

const staff = new OidcAuthDanceComponent({
	issuer: "https://sso.example.com/realms/staff",
	clientId: "auth-dance",
	clientSecret: process.env.SSO_CLIENT_SECRET!,
	redirectUrl: "https://app.example.com/callback",
});
```

> **Note:** A `sub` names an account at one issuer only, and two issuers can give the same `sub` to two persons. Give each issuer its own step name. A new step name or a new issuer makes every linked account unusable.

## Keep more about the account

By default the record holds only the id of the account. To keep more, extend the provider class and override `retrieveIdentification`:

```ts
import { GitHubAuthDanceComponent } from "auth-dance/components/oauth2/github";
import type { OAuth2Identification, OAuth2TokenResponse } from "auth-dance/components/oauth2";

class MyGitHubAuthDanceComponent extends GitHubAuthDanceComponent {
	async retrieveIdentification(token: OAuth2TokenResponse): Promise<OAuth2Identification> {
		const profile = await this.retrieveProfile(token);
		return { identification: String(profile.id), data: { login: profile.login } };
	}
}
```

`data` goes in the private data of the record, and `/list-components` drops it. The component gets the data when it links the account, and a sign-in does not refresh it. Return a value for `identification` that never changes for the life of the account: an email address or a login name can change.

## Another OAuth 2.0 provider

For a provider that speaks plain OAuth 2.0, extend `OAuth2AuthDanceComponent` from `auth-dance/components/oauth2`, give its endpoints, and implement `retrieveIdentification`:

```ts
import { OAuth2AuthDanceComponent, type OAuth2Identification, type OAuth2TokenResponse } from "auth-dance/components/oauth2";

class ExampleAuthDanceComponent extends OAuth2AuthDanceComponent {
	constructor(options: { clientId: string; clientSecret: string; redirectUrl: string }) {
		super({
			...options,
			endpoints: {
				authorizationUrl: "https://provider.example.com/oauth/authorize",
				tokenUrl: "https://provider.example.com/oauth/token",
			},
		});
	}

	async retrieveIdentification(token: OAuth2TokenResponse): Promise<OAuth2Identification> {
		const response = await fetch("https://provider.example.com/api/me", {
			headers: { Authorization: `Bearer ${token.access_token}` },
		});
		const account = await response.json();
		return { identification: String(account.id) };
	}
}
```

Throw `InvalidPromptValueError` in `retrieveIdentification` to refuse an account. Any other error fails the request.
